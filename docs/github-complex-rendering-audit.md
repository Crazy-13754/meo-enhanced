# GitHub README 复杂文档渲染对照

先整理样例、上传私有测试仓库并检查差异，随后仅修复 GitHub 预设的兼容问题。下面保留初次对照证据，并记录修复后的结果。

## 2026-10-10 修复结果

- **标题链接**：对齐标点、连续空格、下划线、标题内链接和公式的锚点规则，并处理重复 ID。复杂文档的 146 个标题 ID 与 GitHub 实页一致；最小样例的原有 GitHub 链接可以跳转。
- **删除线**：GitHub 分支保留 HTML `<del>`；默认分支的标签规则不变。
- **公式边界**：对齐无空格分隔、列表、脚注及块内空行的识别行为。复杂文档从 39 个公式收敛到与实页一致的 14 个，最小样例为 8 个。继续使用 KaTeX。
- **脚注**：脚注内的 Mermaid 和 `math` 围栏保留代码，公式保留源码；正文图表数量与实页一致，均为 16 个。
- **图表样式**：GitHub Preview 与 HTML/PDF 共用独立的 Mermaid 配置，调整节点配色、阴影、字体、换行宽度和间距。三节点短图为 632×144px，与实页一致；分支图为 720×264px，实页为 726×270px；长顺序图高度均为 1744px。移除 GitHub Preview 为复制按钮额外预留的 24px 顶部空间。
- **预设切换**：图表缓存同时区分明暗主题和预设。同一主题下切换默认 / GitHub 也会重新渲染，切回默认恢复原有图表样式和尺寸。
- **完整文档**：生产 Preview 的宽窄面板均无整体横向溢出，24 处图片均加载；表格、列表、任务和脚注数量保持一致。原始文件未修改。

复杂嵌套 Mermaid 仍有布局差异：同为 1012px 正文宽度时，复杂图容器由修复前约 1988px 改善为约 2678px，GitHub 为约 3302px。节点形状、子图布局和连线路由尚未完全对齐；本轮没有更换共享 Mermaid 引擎，以免影响默认预览。不将这些结果表述为所有图表已完全一致，也不使用未经测量的还原度百分比。

验证覆盖预设渲染、Host 协议、生产 Preview 的菜单和同主题切换、目录视口、Mermaid 生命周期、公式解析与布局、实际 HTML/PDF 导出及 Word 隔离。完整复杂文档另做了输入一致性、公式/图表数量、图片加载和锚点跳转检查。最终类型检查、架构检查、构建和构建产物的 Node 运行检查均通过。真实 VS Code 的滑块绘制与拖动、本轮深色 GitHub 实页仍未重测。

## 初次发现的差异（修复前）

| 问题 | GitHub 实际表现 | 本地 GitHub 预设（修复前） | 影响与建议 |
| --- | --- | --- | --- |
| 标题锚点算法不同 | `P16 · Anchor / punctuation` 的链接是 `#p16--anchor--punctuation`，能够跳转 | 标题 ID 为 `p16-anchor-punctuation`；点击相同链接后阅读位置不变 | 会让 GitHub 已有的文档内链接失效。优先在 GitHub 分支使用相同锚点规则 |
| HTML `<del>` 被过滤 | 保留删除线 | 保留文字，但删除线消失；`<s>` 和 Markdown `~~...~~` 正常 | 改变正文表达的含义。补齐 GitHub HTML 标签处理，保持默认分支行为 |
| 公式识别范围过宽 | 有空格的 `$a+b$` 会渲染；紧贴文字的若干写法保留源码；样例中的列表内公式块也保留源码 | 上述写法全部渲染 | 用户可能以为发布到 GitHub 也会显示公式。先对齐语法边界，换 MathJax 不能解决此问题 |
| 脚注内富内容处理不同 | 脚注里的公式保留 `$...$` 源码，Mermaid 保留代码块 | 公式和 Mermaid 均渲染 | S14、S15、S17 等脚注外观和高度不同。GitHub 分支应按实际结果处理这些上下文 |

### 最小样例确认的公式边界

以下结果来自独立的 72 行样例，排除了复杂文档中其他内容的干扰。

| 用例 | GitHub | 本地（修复前） |
| --- | --- | --- |
| P01、P03：公式前有空格，英文或中文正文 | 渲染 | 渲染 |
| P02、P04：公式紧接冒号，无空格 | 原样显示 | 渲染 |
| P05：段落只有公式 | 渲染 | 渲染 |
| P06：标题内有空格的公式 | 渲染 | 渲染 |
| P07、P08：表格中独立公式，或与文字以空格分隔 | 渲染 | 渲染 |
| P09：表格中公式紧接中文冒号 | 原样显示 | 渲染 |
| P10、P12：顶层或引用中的公式块 | 渲染 | 渲染 |
| P11：列表项中的公式块 | 原样显示 | 渲染 |
| P13：脚注中的行内公式和公式块 | 原样显示 | 渲染 |
| P14：脚注中的 Mermaid | 代码块 | 图表 |

这不是“GitHub 不支持表格或标题公式”。决定结果的因素包括分隔符和容器上下文。复杂文档中 GitHub 实际生成 14 个公式节点，修复前本地生成 39 个，主要差异不能归为公式字体或间距。

## 初次 Mermaid 对照（修复前）

**Mermaid 复杂布局差异较大。** S01 的短图在 GitHub 的 SVG 为约 632×144px，本地为 488×70px；“复杂 Mermaid 布局与长文字换行测试”的 GitHub 图表容器高约 3302px，本地约 1988px，正文宽度同为 1012px。节点配色、留白和长标签换行也有差别。居中已经正常，但复杂布局仍应继续校准。不要仅通过拉伸 SVG 消除尺寸差异，应检查 GitHub 分支的 Mermaid 配置和颜色覆盖。

公式字体、符号间距、系统字体回退和代码词法高亮的细微差异仍可接受。建议继续保留 KaTeX，先解决上面的语法与内容差异；界面仍使用简短的整体偏差提示，不扩大说明文案。
